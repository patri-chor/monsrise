# 决策树阵型 AI —— 架构与思路

> 本文档记录"树级遗传算法 + 分离测试 + 识别学习"三合一训练体系的架构设计与演进。
> 代码位置：`src/engine/tree/`（基因/算子/评估/优化器）、`src/engine/train/`（bench 与旧 RL 栈）。

---

## 一、核心设计：识别系统从"硬编码标签"变成"可进化特征"

### 问题缘起
原 bundle 的 `selectBranch` 用硬编码 label 关键词（"对方是祷徒/上钻头/是dof"）匹配分支，
识别逻辑固化在代码里，无法学习，且 label 是给人看的注释而非基因。

### 三层架构
```
基因层  EvolFormation = 固定卡组 + 放置树 EvolNode + FeatureMask
        FeatureMask = tags[]（体系标签，可进化）
          ↓ 变异（tree_ops.ts）
执行层  loadCustomFormation 注入 bundle + patch selectBranch
        → tags 匹配替代 label 关键词，但精确复刻原生两阶段+体系优先级
        → 特殊怪兽索敌（矿爆/铁甲/咒法）原样复用 special_calculator
          ↓ 评估
评估层  arena.ts 分离测试（攻击/生存/盾流/dof 四维）
        eval_vs_random.ts 规则随机基线
```

## 二、识别标签设计（用户提案，待实现）

> 目标：标签不封闭、不过于稀疏。用**经验**给出好架构，而非完全放开的 DNF。

### 三层识别（多标签可选，预留新增接口）

1. **流派识别**（判据已定，见下方"流派识别判据"）
2. **关键怪兽位置**
   - 特殊怪：冲锋106 / 钻头116 / 铁甲117 / 忍猴119 + 突突114 / 咒法107 / 矿爆113
   - 只对这些关键怪编码位置特征，大幅缩小特征数，避免稀疏
3. **核心怪兽处理**
   - 四费核心（102/108/115/118/101/120 等）
   - 上一局输出最高 / 击杀最多的怪兽，需要针对性应对

## 三、流派识别判据（用户定案）

### 识别输入范围
- 对手**开局可见前 4 张手牌（含徽章）** + 随回合加入**场上已部署怪**。

### 三主标签（互斥，按优先级短路：祷徒 > 半冲 > 全冲）

| 优先级 | 标签 | 判据 | 怪兽 ID |
|---|---|---|---|
| 1 | **祷徒** | 有学徒103，或 有祈祷105+守卫112 | 学徒103 / 祈祷105 / 守卫112 |
| 2 | **半冲** | 有祈祷105 且 无学徒103 | 祈祷105 |
| 3 | **全冲** | 突突114/矿爆113/咒法107 中 **≥2 个** | 突突114 / 矿爆113 / 咒法107 |

- 三者都不命中 → 未识别流派（走主分支兜底）。
- 注意：无祈祷无学徒的卡组不一定就是全冲/半冲（但肯定不是祷徒）；
  只有突突/矿爆/咒法出现 ≥2 个才判定为全冲。

### 三附加标签（不互斥，可与主标签叠加、可两两组合，一般最多 3 标签）

| 标签 | 判据 | ID |
|---|---|---|
| **dof** | 凋零2 或 (中毒25+三振王124) 或 肃清哥101（元素涌动4 已移除：误报多） | 凋零2 / 中毒25 / 三振王124 / 肃清哥101 |
| **盾流** | 携带(预防11/反甲30/加固28)中 **≥2 个** | 预防11 / 反应装甲30 / 加固28 |
| **礼物** | 礼物33徽章（目前无阵型） | 礼物33 |

### 组合规则
- 主标签：全冲/半冲/祷徒 **互斥**，按优先级短路取一个；都不命中 = 未知。
- 附加标签：dof/盾流/礼物 不互斥，可与主标签叠加（如"祷徒+dof"），
  也可两两组合，一般只有两个标签，最多三个。

### 己方信息不进标签（用户定案）
- **己方手牌/预算/已部署怪**：训练时输入（避免重复放怪），但进网格的是"正确数据"，
  故**不写入识别标签**。
- **比分差**：训练时才关注，不写入识别标签。

**结论**：识别标签只含"对手流派 + 关键怪位置 + 核心怪"三类对手特征；
己方执行信息（手牌/预算/回合数）与比分差在**训练输入**里单独提供，不进标签。

## 四、特殊怪计算器（special_calculator）处理方式

### 现状：特殊怪不参与树坐标，由独立计算器动态索敌
特殊怪（`SPECIAL_IDS`：冲锋106/咒法107/突突114/钻头116/铁甲117）和瞄准怪
（`AIM_IDS`：矿爆113/塞雷118）**不参与变体**，由 `special_calculator.ts` 根据场上
信息动态计算坐标（矿爆锁祈祷行 x+6、铁甲贴带防装队友、咒法安全位 x+6 等）。

### 树中的表示
树节点 placement 里，特殊怪只存一个**参考坐标**（defaultX/defaultY），执行时
`computeSpecialPosition` 忽略参考坐标、按场上信息重算实际落点。

### 树翻转/变体能否减小树大小？
- 现有 `applyVariant`（mirror_global 上下翻转 / mirror_imperial 帝国轴翻转 / shift 平移）
  已经实现"一套树坐标 + 运行时变体"。
- 特殊怪不参与变体（翻转会破坏其索敌语义，如矿爆必须锁祈祷行）。
- 普通怪可通过翻转复用同一份树坐标，**不额外占树节点**。

### 预期树大小
- 现有 7 套阵型：每套树 3-7 个分支节点（主分支 + 2-3 个条件分支），placement 每节点 1-2 只。
- 进化后预期：**每套阵型树 ≤ 10 节点、每节点 ≤ 3 placement**，分支数 ≤ 3（受 addBranch 上限约束）。

## 五、当前状态与卡点

- 架构端到端跑通，沙盒 vs 网页战斗 60/60 逐位一致。
- 识别系统当前是 5 个封闭体系标签（prayer/fullrush/suqing/drill/rush），**泛用性不足**，
  待升级为用户提出的三层识别。
- 规则随机基线口径：**Python 训练栈口径（跨回合维护手牌）**，真实基线肃清 85% 不败率。
