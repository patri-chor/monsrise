# T004 — Tree Optimizer Observation Gate

> DeepSeek decision task for Antigravity execution.
> Prerequisite: T003 is complete in commit `1e1645d`. This task reinforces T003; do not redo it.

## Objective

Make first-branch induction work on a linear tree, where no conditional branch exists yet. Branch optimization must use observations available at the exact planned fork round and candidate side, never an opponent's full deck or a later-round observation.

## Why

T003 correctly added runtime-trace sampling, cache reuse, validation seeds, and tree-fingerprinted experience keys. Two gaps remain:

1. `sampleFromTrace` currently depends on `BranchDecision`. That event is generated by `selectBranch`; a linear tree before its first conditional branch may not emit it, leaving all initial samples empty.
2. Observed matching currently accepts an opponent if it matched at any round. A feature first visible in R3 must not make an R1 branch appear triggerable.

## Required Design

### A. Decouple observation from branch selection

1. Add an observation callback/type in `arena.ts` with `round`, candidate `side`, `handIds`, `handBadges`, and `boardIds`.
2. In `bundleRoundPlanFor`, emit one observation before `decideWithFormation` on every round with a non-empty hand. It must not depend on `selectBranch` being called.
3. Let `playSpecVsSpec` collect A-side observations and return them while preserving existing `BranchDecision` behavior and callers.
4. Let `MatchTrace` retain both actual observations and actual branch decisions if useful.
5. Initial induction samples and crash diagnostics must derive from observations. Only an unplayed/early-ended round may have no sample. Score `0` remains a valid draw.

### B. Exact fork-round and side matching

1. Implement observed matching using `(mask, forkRound, trace)`.
2. For a non-side mask, recognize only `trace.observations.get(forkRound)` and call `matchMask(mask, rec, trace.side)`.
3. For a side mask, require both `trace.side === mask.side` and an observation at `forkRound`.
4. Do not fall back to static full-deck matching when no actual observation matches. Log a clear reason and return `null`/decline creating the branch.
5. Static deck recognition may be retained only as explanatory logging; it cannot affect acceptance, evaluation, or trigger coverage.
6. Include in `searchValidation`: `forkRound`, per-opponent/per-side observed trigger coverage, and counts for early-ended/no-hand/mask-miss.

### C. Finish experience-key isolation

1. `computeTreeFingerprint` must be pure. Sort copies of `subs`/`keys`, never mutate the passed tree.
2. In `focused_climb.ts`, calculate the current tree fingerprint each iteration and pass it to both `replaceKey` and `moveKey`.
3. Old experience JSON must remain readable. Unfingerprinted old keys must not block new fingerprinted keys.

## Acceptance

- [ ] A linear tree with no conditional child produces an observation/sample for every played R1-R5 round; this does not require `selectBranch`.
- [ ] A key first visible in R3 cannot match an R1 fork, but can match an R3 fork.
- [ ] No actual match at fork round causes no branch adoption; no full-deck fallback is used.
- [ ] Fingerprinting leaves input `subs`/`keys` order and values unchanged.
- [ ] Both `branch_induct` and `focused_climb` use tree-fingerprinted experience keys; different trees do not share invalid-operation entries.
- [ ] Existing T003 test cases still pass, plus focused tests above.
