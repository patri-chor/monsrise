## 1. Executive Summary & Root Cause Analysis

本任务按照 T012 规范彻底排查并修复了前四种子周期及测试套件运行时的**模块导入期副作用与输出路径未隔离问题**，建立了严格的生产文件 byte-identical 回归防护体系：

### 1.1 根因定位 (Root Cause Analysis)
- **根因**: 历史模块 [`src/engine/tree/candidate_retention.ts`](file:///d:/develope/monsrise1/src/engine/tree/candidate_retention.ts) 与 [`src/engine/tree/first_four_generation.ts`](file:///d:/develope/monsrise1/src/engine/tree/first_four_generation.ts) 底部的 CLI 执行入口守卫使用了 `if (!isTesting)`。在被测试文件动态导入（或未显式提前置入环境变量）时，模块被作为依赖加载，触发了顶层 CLI 分析函数，导致向默认目录 `reports/new-formation-pilot/` 写入了 `retention.json` / `retention.md` 并输出了日志。
- **修复措施**:
  1. 引入严格的直接执行守卫 `isDirectScript`：
     ```typescript
     const isDirectScript = Boolean(
       process.argv[1] &&
       (process.argv[1].endsWith('candidate_retention.ts') || process.argv[1].endsWith('candidate_retention.js'))
     );
     if (isDirectScript && !isTesting) { ... }
     ```
     彻底杜绝任何被导入模块在 import-time 产生任何副作用或文件写盘。
  2. 显式化所有输出路径：`first_four_generation.ts` 内部所有产物写入均严格绑定传入的 `outputDir`，默认生产路径为 `reports/new-formation-generation/first-four-cycle/`，测试时显式传入临时路径 `tests/.tmp/first-four-generation/`。
