## 1. 架构设计与调用链 (Architecture & Call Path)

本任务严格实现 Generation 2 核心地基架构：
- **单回合真实产品执行引擎与检查点 (`ProductGameSession` & `ProductRoundCheckpoint`)**：
  - 复用权威游戏状态机（`gameEngine`、`battleSystem`、`vfx` 与 `badgeSystem`），杜绝编写重复简化的战斗模拟器；
  - 导出战前完全独立且自包含的 `ProductRoundCheckpoint`（包含棋盘、手牌、预算、分数、RNG状态）；
  - 支持从检查点无损恢复并执行单回合产品战斗续玩（`session.playRound`）；
- **全保真门禁 (`Round Engine Fidelity Gate`)**：
  - 证明连贯 `playFullGame` 与单回合驱动 `ProductGameSession` 在胜负、比分、回合序列、部署轨迹、站位、预算扣除上 100% 精确等价；
  - 验证断点恢复重放（Checkpoint Replay）输出一致性；
- **全二冲 (all2rush) Loss-Case 盘点与局部分支变体搜索**：
  - 自动挖掘对战 `golden_boom`、`all2prayer`、`gift_jungle` 的真实失利点，捕获 pre-R Checkpoint；
  - 针对每个 Case 在固定对局环境下采样最多 48 个 1-3 变量组合变体（R 放置坐标、部署顺序、Policy 参数）；
  - 从 pre-R Checkpoint 进行单局续玩探索，替代百局全量跑板；
- **分支库存储与生命周期管理 (`Branch-First Library`)**：
  - 探索出的更优解首先存入分支库为 `EXACT_CASE_BRANCH`；
  - 提供前缀合并 (`MERGED_PREFIX_BRANCH`) 与重复行为剪枝 (`PRUNED_HISTORICAL`)；
  - 严格保持全局主树、T0-T3 梯队、L1 权重与现网部署零改动（No-Apply Constraint）。

调用链结构：
```text
LossCase(target, opp, side, seed, pre-R Checkpoint)
  -> generateFocusedCandidatesForCase(1-3 vars, <=48)
  -> ProductGameSession.restore(preRCheckpoint)
  -> playRound(...) continuation
  -> EXACT_CASE_BRANCH
  -> mergeAndPruneBranches(MERGED_PREFIX_BRANCH / PRUNED_HISTORICAL)
  -> append-only Evidence JSONL
```
