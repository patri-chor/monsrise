# T006 Acceptance - New Formation Generation Pilot

## Decision

Rejected for correction. The committed implementation `ba1c39b` passes dry-run structural tests, bounded termination, output isolation, and active-library non-mutation, but it does not meet two core data-validity requirements.

## Verified

- `npx vite-node tests/new_formation_pilot.test.ts` passes 3/3:
  - dry-run creates six structurally valid, deduplicated records over three paths;
  - an oversized request terminates at the explicit attempt cap;
  - `FORMATION_LIBRARY` remains unchanged.
- Outputs are isolated under `reports/new-formation-pilot/`.
- Worker count is clamped to 1..4.
- `npx tsc --noEmit` has no reported error in the new pilot/test files; repository-wide failures remain pre-existing elsewhere.

## Blocking Findings

1. **P1 - recorded evaluation seeds are not the seeds actually executed.** `new_formation_pilot.ts` writes coarse/refined `seedBase` metadata and reports distinct bases (`1000` and `9000`), but both calls invoke `evaluateBatchParallel` without a seed argument. The evaluator hard-codes task seeds to `7000/8000/9000/10000` on every call. Therefore the coarse and refined passes use overlapping, in practice identical per-candidate seed schedules. This fails T006 acceptance item “Coarse/refined evaluations use distinct fixed seed bases” and makes the output metadata false.

2. **P1 - the pilot reimplements the assembly rules instead of reusing the existing generation helpers.** `new_formation_pilot.ts` copies skeleton, candidate-pool, badge-selection, and validity logic from `generate_variants.ts`, while its deck construction differs materially (one random output versus the existing output-pair assembly). This violates the required use of existing generation helpers and creates two diverging definitions of a valid generated formation.

3. **P2 - tree mapping ignores the selected archetype.** Every generated candidate maps its deck through the `全二永平` reference tree, regardless of whether the source path is `prayer`, `halfrush`, or `fullrush`. This weakens the declared archetype-path semantics and should be corrected while consolidating assembly/mapping.

## Follow-up

T007 is the corrective implementation task. Do not use the current T006 evaluation results for ranking, adoption, training data, or later deployment decisions. Keep all candidate output isolated and do not mutate the active library.
